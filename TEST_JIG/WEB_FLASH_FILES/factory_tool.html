📋 Operational Flows Guide

Complete step-by-step procedures for every workflow in the Spatika Factory Jig system.

🆕
Flow A: Full Factory Flash & Test
New boards — first-time programming
TAB: Board QC
1
Start local server (launch_mac.command) and open factory_tool.html in Chrome.
2
Firmware auto-loads from WEB_FLASH_FILES/. Step 1 shows LOADED.
3
Select Tester Name and Profile (TRG / TWS / TWS-RF) from the top bar.
4
Connect board via USB → click 🔌 Connect Board. Cursor auto-jumps to ESP32 barcode field.
5
Scan ESP32, GPRS, and Nuvoton barcodes with scanner.
6
Confirm Option 1 is selected. Click 🚀 Start Test.
7
Board is prepared, QC firmware flashed, diagnostics run automatically. Monitor live checklist on the right.
8
On QC PASS, Google Sheets sync occurs. Click 🧹 Start Next Board or go to 📦 Enclosure Integration.
💡 Use this flow for every newly assembled board before enclosure integration.
🔧
Flow B: Flash Production Firmware Only
Re-flash app — preserve settings & calibration
TAB: Board QC
1
Connect board and wait for software LOADED + CONNECTED status.
2
Scan board barcodes.
3
Select "Update Software Only". Make sure "Wipe chip before testing" is unchecked to keep existing settings.
4
Select the correct Config (e.g. KSNDMC_TRG, BIHAR_TRG) from the top bar.
5
Click 🚀 Flash Production Firmware. Only the app software is written — no tests run.
⚠️ Do NOT check "Wipe chip" for this flow — it would erase the board's existing settings.
📦
Flow C: Enclosure Integration
Assembly line — place tested boards into enclosures
TAB: Integration
1
Click the 📦 Enclosure Integration tab.
2
Connect a QC-passed board. Cursor auto-jumps to Box 1 input.
3
Scan Box 1 (DL Box) barcode — the system auto-fills the other barcodes from the database.
4
Scan Box 2 (PS Box) and confirm all component barcodes are correct.
5
Select the correct Config from the top bar. Click ⚡ Flash & Verify.
6
The board record is saved automatically to Google Sheets — no further action needed.
💡 Always scan Box 1 first — it automatically fills in all the other barcode fields.
🛠️
Flow D: Servicing & Repair
Replace parts, re-flash repaired units
TAB: Repair
1
Click the 🔧 Servicing & Repair tab.
2
Scan Box 1 barcode — the system loads the previous record automatically.
3
Re-scan all component barcodes (scan new/replacement barcodes if parts were swapped).
4
Type the Reason for Servicing (required — used for records).
5
Click ⚡ Flash & Verify. The system detects changed barcodes and logs the swapped parts.
⚠️ If a board is in the Failed Boards Bin, it must be resolved there first before repair can proceed.
🔬
Flow E: Live Diagnostics Only
Check sensors without loading any software
TAB: Board QC
1
Connect a board that already has test software on it (no software loading needed).
2
Scan the board barcode sticker(s).
3
Click ▶ Start Diagnostics in the left panel. The board output streams to screen.
4
Follow on-screen instructions (LCD check, keypad test, rain jumper test). The right panel shows live results.
5
Click 💾 Download QC Log to save the test report at any time.
💡 Use this for re-checking sensors or troubleshooting without changing any software.
🗑️
Flow F: Failed Boards Bin
Review and manage boards that did not pass
TAB: Failed Bin
1
Click the 🗑️ Failed Boards Bin tab. All failed boards appear in a list.
2
Use the filter buttons (All / ESP32 / GPRS / Nuvoton / MPPT / Battery) to find the type of problem.
3
Read the failure reason and test time shown for each board.
4
If the board has been repaired, switch to 🔧 Repair tab and use Flow D to re-test it.
5
For boards to be scrapped, use the Google Sheets report to mark them archived.
⚠️ Failed boards cannot be used in Integration or Repair until they are cleared. This stops bad boards from entering enclosures.

📖 Spatika Factory Jig — User Manual

🔷 Quick Start

  1. Open the tool via launch_mac.command or launch_windows.bat to auto-load firmware.
  2. Select your Name and Profile (TRG / TWS / TWS-RF) from the top bar.
  3. Connect the board via USB and click 🔌 Connect Board.
  4. Scan the barcode stickers on each board — the cursor moves automatically.
  5. Choose the correct option (New Board = Full Test, Already Tested = Update Software Only).
  6. Click 🚀 Start Test (or the relevant action button) and follow on-screen instructions.

🔷 Profile Guide

TRG Rain-only board. RF rain test active. Wind tests skipped.
TWS Wind + Rain board. RF rain test skipped (uses tip mechanism).
TWS-RF All-sensors board. RF rain + Wind + all tests active.

🔷 Interactive Test Steps (Section C)

  • 📟 Nuvoton LCD — Confirm the LCD screen is showing text when prompted.
  • ⌨️ Keypad — Press each key in order: CLEAR → LEFT → UP → DOWN → RIGHT → SET.
  • 🌧️ Rain RF Test — Connect loopback jumper GPIO 2 → GPIO 34, then trigger 10 rain pulses. Must count exactly 10.
  • 💤 Sleep/Wake Test — Board sleeps; press SET key to wake it. Screen shows WAKEUP: PASS!

Test Component Testing Verification Method Target PASS Bounds / Values
Internal SPIFFS Mounts partition and writes test string. File reads back matching test pattern.
SD Card SPI Mounts FAT card and writes test file. Mount successful, read-back ok.

Wind Direction Reads ADC value on GPIO 39. Real-time voltage fluctuates on vane turn.

🔷 5. Interactive Keypad Mapping

The Nuvoton UI board sends ASCII key characters to the ESP32 on UART1 when keys are pressed:

  • CLEAR (Raw character `'1'`): Clears LCD and passes LCD visual test.
  • LEFT (Raw character `'2'`): Keypad sweep step 1.
  • UP (Raw character `'3'`): Keypad sweep step 2.
  • DOWN (Raw character `'4'`): Keypad sweep step 3.
  • RIGHT (Raw character `'5'`): Keypad sweep step 4.
  • SET (Raw character `'6'`): Keypad sweep step 5 + triggers EXT0 deep sleep wakeup.

🔷 6. EXT0 Deep Sleep Wakeup Test

After the keypad sweep the firmware initiates a deep-sleep sequence to verify the hardware wakeup path:

  1. Firmware powers down the Nuvoton LCD (GPIO 32 LOW) and GPRS modem (GPIO 26 LOW).
  2. ESP32 enters deep sleep with EXT0 wakeup configured on GPIO 27 (active LOW).
  3. Operator presses the EXT0 button. This drives GPIO 27 LOW.
  4. ESP32 reboots from deep sleep. The dashboard detects the SLEEP:PASS serial token.
  5. LCD displays WAKEUP: PASS! and the QC checklist marks the step green.

⚠️ If the EXT0 button is not available, use Force Pass (CMD:SLEEP_PASS) in the Operator Instructions box to skip this step.
