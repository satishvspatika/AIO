📖 Spatika Factory Jig — User Manual

Dashboard v6.07 · Last updated Jun 2026 · Auto-generated

🔷 Overview

The Spatika Factory Jig is a self-contained browser-based tool for flashing, testing, and auditing newly assembled AIO ESP32 boards. It runs entirely in Chrome / Edge over a local HTTP server — no drivers or native apps required.

It handles: chip detection & auto-sizing, QC firmware flashing, live serial diagnostics, checklist tracking, tester identification, automatic Google Sheet sync, and downloadable QC reports.

🔷 Header Bar

Spatika Jig Title badge. The pill next to it shows the current board connection state (CONNECTED / DISCONNECTED).
Tester: Select the operator's name from the dropdown (Prasad, Rajesh, Prashant, Rishi, Naveen, Chethan, Madhu, Guest). Choose Other / Custom... to type a free-form name or ID. The name is saved automatically and restored on next load.
Audit: Selects the context in which this test is being run. See Verification Audit Modes section below.
Profile: Selects the hardware test profile — drives which QC tests are active and which release configs are available in the Config dropdown.
  • TRG — Rain-only board. RF rain test active. Wind tests skipped.
  • TWS — Wind + Rain board. RF rain test skipped (pulse via tip mechanism).
  • TWS-RF — All-sensors board. RF rain + Wind + all tests active.
Config: Selects the named release configuration to use for production flashing. Options change automatically with the Profile:
  • TRG → KSNDMC_TRG · BIHAR_TRG · SPATIKA_GEN
  • TWS → KSNDMC_TWS · KSNDMC_TWS-AP
  • TWS-RF → KSNDMC_ADDON · SPATIKA_GEN
A green LOADED badge appears once firmware.bin for the selected config is in the vault.
TALLY Cumulative session counter: PASS count, FAIL count, and overall yield %. Persists across page reloads in browser storage. Click Reset to clear at the start of a new batch.

✅ Step 1 — Firmware Vault

The dashboard automatically fetches all core firmware binaries from its serving directory (./). Core vault files:

  • bootloader.bin, boot_app0.bin — boot sector
  • partitions_4/8/16mb.bin — partition tables per chip size
  • qc_test_4/8/16mb.bin — QC diagnostics firmware
  • production_4/8/16mb.bin — generic production app (fallback)

If files are missing a 📁 Select Firmware Folder button appears. Select the WEB_FLASH_FILES/ root folder. The scanner:

  • Loads all top-level core binaries automatically.
  • Recursively finds subfolders named after known configs (e.g. KSNDMC_TRG_8mb/) and loads their firmware.bin, fw_version.txt, and metadata.json.

📦 Firmware Build Info panel

After a config folder is loaded, a Firmware Build Info panel appears below the vault showing the exact compile-time settings baked into that binary:

🐛 Debug ON/OFF  ·  🌐 Web Server ON/OFF  ·  📟 Nuvoton UI YES/NO
💊 Health Report ON/OFF  ·  ⏱ Health Frequency  ·  🌧 RF Resolution (mm)
💨 Wind Teeth Count  ·  📅 Build Timestamp

⚠️ If the selected binary exceeds the app partition size for the detected chip, a red size warning appears and the Start Programming button is blocked until you switch to a compatible chip size (8 MB or 16 MB).

✅ Step 2 — Device Connection

Connect the board via USB, then click 🔌 Connect Board. The browser shows a port selector — pick the correct COM/tty port. On success:

  • The ESP32 chip MAC address and auto-detected flash size (4 / 8 / 16 MB) appear in the header.
  • The 🔄 Reset Board button becomes visible to hardware-reset the board without reflashing.
  • A CONNECTED badge replaces DISCONNECTED.

⚠️ Close Arduino IDE Serial Monitor or any other terminal before connecting.

✅ Select Subsystems to Test

Three checkboxes control which hardware modules are active during the test run:

  • 📁 ESP32 Board — SPIFFS, SD Card, RTC, ADC power rails, Solar input, Rainfall RF
  • 📶 GPRS Cellular Modem — AT command boot, IMEI, SIM CCID, signal strength (CSQ)
  • 📟 Nuvoton LCD / Keypad — LCD display verification, full keypad button sweep

Unchecking a module greys it out in the Live Diagnostics panel immediately and the firmware is told to skip it via a handshake command (CFG:ESP,GPRS,NUV). The Google Sheet verdict records exactly which subsystems were active, e.g. PASS (ESP+GPRS).

✅ Step 3 — Run Programming

Two flashing modes are available:

Option 1 — Full Factory Flash Erases the entire chip, auto-detects flash size, flashes bootloader + partition table + QC firmware, runs live diagnostics, then flashes the Production application. Use for new boards.
Option 2 — App-Only Update Writes only the latest production binary at offset 0x10000. Preserves calibration data and filesystems. Takes < 5 s. Use for firmware upgrades.

⚠️ The 🚀 Start Programming button is disabled until a Tester name is selected, the board is connected, and the required firmware files are loaded.

✅ Release Config Deployment (Named Firmware)

When deploying production firmware from a named release (received via email ZIP or from WEB_FLASH_FILES/):

  1. Select the device Profile (TRG / TWS / TWS-RF) in the header bar.
  2. Select the matching Config (e.g. KSNDMC_TRG) from the Config dropdown.
  3. Click 📁 Select Firmware Folder and point to the WEB_FLASH_FILES/ directory.
    The dashboard recursively scans it and loads the config-specific binary from the matching subfolder (e.g. KSNDMC_TRG_8mb/firmware.bin).
  4. The Firmware Build Info panel appears showing Debug, WebServer, Nuvoton, RF resolution, and build date — so you always know exactly what was compiled in.
  5. Connect the board and click 🚀 Start Programming. The named config binary is used instead of the generic production binary.

💡 Receiving the release ZIP by email and extracting it produces the identical subfolder structure. Simply copy the extracted folders into WEB_FLASH_FILES/ or serve the extracted ZIP folder directly.

✅ Live Diagnostics Checklist

After flashing (or by clicking ▶ Start Diagnostics directly), the dashboard opens a serial read loop and parses tagged output lines from the QC firmware in real-time, updating three sections:

⚡ Section A — Automatic Hardware Sweep

  • 📁 Internal SPIFFS — write/read test on internal flash filesystem
  • 💾 SD Card — mount and detect SD module
  • 🕒 Real-Time Clock — I²C communication test with DS1307 (addr 0x68)
  • 📶 WiFi Scanner — verify WiFi radio by performing network scan
  • 🌡️ Env Sensor — auto-detect I²C Temp/Hum sensor (HDC1080/HDC2022 at 0x40, BME280 at 0x76/0x77) and verify readings
  • 📶 GPRS Cellular — AT boot, IMEI retrieval, SIM CCID, CSQ signal strength

🔋 Section B — Power Status Indicators

  • 🔋 ESP32 Battery — ADC rail check, nominal 3.2 V (pass range 3.0–3.6 V)
  • ⚡ GPRS Battery — ADC rail check, nominal 3.7 V (pass range 3.5–4.4 V)
  • ☀️ Solar Input — Solar panel voltage from dedicated ADC channel

🎮 Section C — User Interactive Tests

  • 📟 Nuvoton LCD — Firmware shows a prompt on the LCD; operator confirms it is readable
  • ⌨️ Keypad Sweep — Firmware asks the operator to press every key (CLEAR → LEFT → UP → DOWN → RIGHT → SET) one by one. All 6 must register before the test passes.
  • 🌧️ Rainfall RF Test — Operator connects a loopback jumper from GPIO 2 → GPIO 34, then triggers 10 simulated rain pulses. Firmware counts the tallied interrupts; must equal exactly 10 to pass.
  • 💤 EXT0 Sleep Wake — Put the ESP32 into deep sleep and verify it wakes up on external key interrupt. The board will turn off the LCD screen and power rails. Press the SET key on the keypad to trigger EXT0 wakeup. The screen will power back on and display `WAKEUP: PASS!`.

✅ Operator Instructions Box

A blue guide box above the diagnostics checklist updates in real-time, telling the operator exactly what to do next (e.g., "Press the LEFT key"). For interactive tests it also exposes Manual Override buttons:

  • ✓ Force Pass / Skip — Sends a serial override command to the board (CMD:LCD_PASS / CMD:KEYPAD_PASS / CMD:RF_PASS / CMD:SLEEP_PASS) to skip a step when the physical keypad/LCD/wakeup pin is unavailable.
  • ✗ Force Fail — Immediately marks the step as FAIL and shows the BOARD FAIL verdict overlay.

✅ Verdict Overlay

When QC completes (pass or fail), a full-screen overlay shows BOARD PASS or BOARD FAIL with a chime and the total test duration. The overlay also triggers:

  • Updating the Session Tally widget (PASS/FAIL/Yield %).
  • Automatically posting the full result to the configured Google Sheet.
  • Enabling the 💾 Download QC Log button.

✅ Google Sheets Integration

Paste your Google Apps Script Web App URL in the Google Sheet Integration card (left panel). Click 📋 Setup Code to view and copy the Apps Script source to deploy.

Each test result writes one row with 22 columns:

Timestamp · Local Test Time · MAC Address · Flash Size · GPRS IMEI · SIM CCID · Nuvoton LCD ·
SPIFFS · SD Card · RTC · Cellular · LCD/UI · Keypad · Rainfall (Tips) ·
Battery (V) · Solar (V) · Firmware Ver · QC Verdict · Tester · Verification Mode · Duration (s) · Approved By

The Approved By column is pre-filled with "Pending Review" — a supervisor can type their sign-off directly in the sheet to approve the row.

✅ Verification Audit Modes

Standard QC Test Normal daily factory testing. Every new board gets this. Results count toward yield metrics.
Supervisory Audit A senior engineer or QA lead is observing the session. Flags the record for mandatory second-level sign-off in the Approved By column.
Random Sampling Testing a statistical subset of boards from a batch — not 100% of production. Used for incoming quality control or batch acceptance.
R&D Diagnostic Board is being tested for development or debugging. Results are not intended to count toward production yield metrics.

✅ Download QC Log

Click 💾 Download QC Log after diagnostics complete. A .txt report is generated containing: Tester name, Audit mode, Test duration, Firmware version, Board MAC, IMEI, CCID, QC verdict, all checklist results, and the full raw serial console log. File is named QC_REPORT_<MAC>_<timestamp>.txt.

⚠️ Tips & Troubleshooting

  • Always serve the dashboard over http://localhost:8000 — the native folder picker and WebSerial API require a secure context.
  • If the board does not connect, close Arduino IDE Serial Monitor or any other terminal holding the port.
  • The Start buttons remain disabled until a Tester name is selected (not Guest alone), the board is connected, and firmware files are loaded.
  • For a new batch, click Reset in the Tally widget to clear the session counters before starting.
  • If a test step freezes, use the Force Pass / Force Fail override buttons in the Operator Instructions box.
  • If a named config binary is too large for the board (e.g. a large 8MB binary on a 4MB chip), a ⚠ red warning appears in the Firmware Build Info panel and Start Programming is blocked. Switch to an 8MB or 16MB board.
  • The Config LOADED badge in the header turns green only when both firmware.bin and either fw_version.txt or metadata.json for that config are in the vault. If the badge is missing, re-select the firmware folder.

Test Component Testing Verification Method Target PASS Bounds / Values
Internal SPIFFS Mounts partition and writes test string. File reads back matching test pattern.
SD Card SPI Mounts FAT card and writes test file. Mount successful, read-back ok.
DS1307 RTC Queries 0x68. Checks tick speed changes. Seconds counter increments over 1.1s.

🔷 5. Interactive Keypad Mapping

The Nuvoton UI board sends ASCII key characters to the ESP32 on UART1 when keys are pressed:

  • CLEAR (Raw character `'1'`): Clears LCD and passes LCD visual test.
  • LEFT (Raw character `'2'`): Keypad sweep step 1.
  • UP (Raw character `'3'`): Keypad sweep step 2.
  • DOWN (Raw character `'4'`): Keypad sweep step 3.
  • RIGHT (Raw character `'5'`): Keypad sweep step 4.
  • SET (Raw character `'6'`): Keypad sweep step 5 + triggers EXT0 deep sleep wakeup.

🔷 6. EXT0 Deep Sleep Wakeup Test

After the keypad sweep the firmware initiates a deep-sleep sequence to verify the hardware wakeup path:

  1. Firmware powers down the Nuvoton LCD (GPIO 32 LOW) and GPRS modem (GPIO 26 LOW).
  2. ESP32 enters deep sleep with EXT0 wakeup configured on GPIO 27 (active LOW).
  3. Operator presses the EXT0 button. This drives GPIO 27 LOW.
  4. ESP32 reboots from deep sleep. The dashboard detects the SLEEP:PASS serial token.
  5. LCD displays WAKEUP: PASS! and the QC checklist marks the step green.

⚠️ If the EXT0 button is not available, use Force Pass (CMD:SLEEP_PASS) in the Operator Instructions box to skip this step.
